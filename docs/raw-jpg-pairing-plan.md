# 同拍 RAW+JPG：配对、合并显示、合并操作

来源：小红书用户反馈。相机同时写 RAW 和 JPG，导入后画廊里是两张，挑片、打星要做两遍。

## 两种「JPG 和 RAW 的关系」

| | 同一次拍摄（本文） | 修图后的导出（添加 RAW 源） |
| --- | --- | --- |
| 来源 | 相机同时写 RAW+JPG | Lightroom / Photoshop 修完导出 |
| 认法 | 确定：同一文件夹、同名、拍摄时间一样 | 模糊：拍摄时间、机身、文件名片段打分 |
| 显示 | 合并成一张，操作一起做 | 两张，检视器里标出原片 |
| 存在哪 | `raw_pairs`（schema 15） | `image_lookup_registry.raw_asset_id` |

「添加 RAW 源」不动：它导入的 RAW 只建索引、不进画廊，专门给导出的成片找原片。两件事互不影响。版本堆叠（`resource_sets`）也不用：那是编辑版本，启动修复（`remove_raw_from_resource_sets`）有意把 RAW 排除在外。

## 已定决策

1. **配对总是记录，合并与否是图库设置。** 设置「同名 RAW+JPG：合并为一张 / 分开显示」随图库走（`app_settings` 的 `raw_pairs`），随时切换，不用重新导入。导入时不弹窗。
2. **新图库默认合并。** 第一次导入就配上时，导入结束提示「N 组 RAW+JPG 已合并为一张」，带「改为分开」。只提示一次。
3. **老图库升级后保持分开。** 迁移时补配已有的照片，但设置写成「分开」，画廊不变；统计页之外只提示一次「发现 N 组，可以合并显示」。这是为了不悄悄改变老用户已经习惯的画廊。
4. **合并时写两张，不只写封面。** 评分、旗标、标签、描述、加入/移出文件夹、从图库删除，sidecar 在命令分发处把 JPG 的 id 扩成「JPG + 它的 RAW」。切回分开时两张都留着打好的值。
5. **配对那一刻两张的值不一样：** 一张有一张没有，用有的；都有，用 JPG 的（封面，用户看到的是它）；标签和文件夹取并集。在「合并」状态下配上、或从分开切到合并时做这一步。
6. **配错了可以拆开。** 拆开的一对记成 `state = 'split'`，再导入也不会重新配。手动配对第一版不做。

## 配对规则

导入时每索引一个文件就找它的另一半（`db/raw_pairs.py` 的 `pair_asset`），和导入顺序无关：

- 一边是 RAW，另一边是 JPG / HEIF（family `jpeg`、`heif`）。
- 同一个文件夹，文件名主干相同（不分大小写）。
- 这个文件夹里同名的 RAW 和 JPG/HEIF 各恰好一张；多了就不配（比如同时有 `IMG_1.JPG` 和 `IMG_1.HEIC`）。
- 两张都有拍摄时间时，相差不超过 2 秒，防止两台相机的 `DSC_0001` 放在同一个文件夹。
- 两张都是导入进图库的（registry 里有）。「添加 RAW 源」索引的 RAW 不参与。
- 已经在一对里（配上的或拆开的）的不再配。

## 合并时各处的表现

- **画廊、数量、筛选、地图、文件夹、智能合集、按清单找图、统计张数：** 配对里的 RAW 不出现。条件写在一处（`raw_pairs.HIDDEN_RAW_CLAUSE`），加在 `_status_clause` 和各个文件夹查询里。
- **「有 RAW」筛选**（`facets._HAS_RAW`）：合并的一对算有 RAW。
- **统计的存储：** 配对的 RAW 文件大小照算（`stats_scope.raw_id` 取配对的 RAW），按类型分的 RAW 字节数不会变少。
- **卡片：** 角标「RAW」。
- **检视器：** 列出 RAW 文件（路径、在访达中显示），提供「拆开」。
- **删除到废纸篓、拷贝文件：** 两个文件一起。
- **MCP：** 写操作走同一个 sidecar 分发，自动一起写；搜索结果只有封面。

## 第一版不做

- 灯箱里切换看 RAW。
- 隐藏的 RAW 跳过 AI 标注、人脸、色板分析（现在照跑，只是费时间）。
- 名字对不上的配对（比如 Pixel 的 `.RAW-01.MP.COVER.jpg`）、手动配对。
- JPG 缺失时拿 RAW 当封面。
