## 先说结论

- **整块死代码已经不多了。** #213 之后剩下的是：一条 dev 专用 catalog 路径、几个注册函数返回了没人接的成员、
  两个 CLI 子命令、每个 catalog 都会建出来的两个空目录、24 个 `db/__init__.py` 里没人经包级 import 的
  re-export、约 60 个「只在本文件用却 export 了」的符号、23 个 spec 里必然立即返回的 `waitForFunction`。
- **结构上真正的债是「同一件事写了 N 份」**，而不是 god file：catalog 守卫 48 处、`*-status` handler 8 处、
  「外点关闭 + Esc」effect ~20 份、`clamp` 7 份、`report_progress` 3 份、token-JSON 解析 3 份（已漂移）、
  job_runner 五个单阶段 job 同一骨架、cli.py 两个 browse handler 38 行逐字相同（**已漂移出一个 bug**）。
- **上一轮立的结构性约束都守住了**：`test:electron` 手写列表与文件系统 0 差异；commands.js 57 个动词每个
  都有调用方；ipcChannels 表无漂移；argparse 307 个参数每个都被 handler 读；Electron 发出的每个动词在
  cli parser 里都存在。
- 顺手发现 6 个 bug（见末段），其中两个用户可见：文件夹视图永远不显示人脸角标；批量拼图导出某页失败仍提示「已导出」。
