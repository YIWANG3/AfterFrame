## 正确性

- [x] **1. 统计只数照片，点开的画廊连视频一起筛**
  `stats.py` 的 `_culling` / 方向 / 评分 / 机身镜头都带 `kind != 'video'`，但 `statsPage.filtersFor` 生成的画廊筛选（`flag: none + rating_max: 0`、`orientation`、`rating_*`）不排除视频。
  main.afcatalog 实测：137 个视频里 129 个没标没评分、137 个都有 display_shape。点「未审阅」画廊会比页面上的数字多 129 张，点横/竖幅也会多出视频。stats.py 文件头写的「both must count the same rows」不成立。
  修法：要么统计口径改成和画廊一致（含视频），要么筛选里带上照片限定（需要筛选栏能显示这一条，否则就是「没说就收窄」）。

- [x] **2. 存储「按年」柱子会把时间范围撑出页面选的区间**
  `filtersFor("year")` 用 `date_from: YYYY-01-01` 覆盖了 base 的 `date_from`。选「近 12 个月」（比如从 2025-12-01 起）时点 2025 的柱子，打开的是 2025 全年，柱子上的字节数只算了 12 月。
  修法：year / month / day 的区间和 base 取交集（`date_from` 取较晚、`date_to` 取较早）。

- [x] **3. 切换时间范围后请求失败，页面继续显示旧范围的数字**
  `StatsView` 切换 range 时不清空 `stats`。新请求失败时 `failed && !stats` 为假，页面停在上一个范围的数据上，范围按钮却已经切过去了，没有任何提示。加载期间也一样显示旧数据。
  修法：range 变化时清掉 stats（或记下 stats 对应的 range，不匹配就显示加载中或失败）。

- [x] **4. 格式统计的口径和它打开的筛选不一致**
  - `_JPEG = {".jpg", ".jpeg"}`、`_HEIF` 是手写的，但格式筛选走 `formats.filter_extensions`（JPEG 家族还有 jfif / jpe / insp）。这些文件在统计里算「其他」，点 JPEG 却会出现。
  - 「RAW+JPEG」用的是 `raw_id IS NOT NULL`，`has_raw` 筛选（`facets._HAS_RAW`）只认 `auto_bound` / `manual_confirmed`。`pending_confirmation` 但带候选 RAW 的照片会两边不一致。
  修法：直接用 `formats.family_sql` 和 `_HAS_RAW` 的定义。main.afcatalog 目前两种都是 0 张，但别的库会撞上。

- [x] **5. 共用一个 RAW 时，「可清理」的字节被重复计算或多算**
  `rejected` 把被拒那一版的 RAW 算成可释放，即使同一个 RAW 还被一个没被拒的版本用着。看起来像的照片那组按 `s.size + raw.file_size` 一个个加，同组成员共用 RAW 时 RAW 字节会算好几次。
  修法：可释放的 RAW 只算「所有引用它的版本都在待删集合里」的那些，并按 raw_id 去重。（main.afcatalog 目前没有同组共用 RAW 的情况。）

- [x] **6. 地点覆盖率可能超过 100%**
  `_places` 不过滤视频，副标题却用 `places.located / photos` 算比例（`StatsView.jsx:424`）。有定位的视频多了，就会出现「110% 有地点」。分母应改用 `overview.total`，或者 `_places` 也只数照片。

- [x] **7. 城市按 city_key 分组，点开却按 city_en 筛**
  同名城市（Portland、Cambridge……）在统计里是两行，点任何一行都会打开两个城市的照片，数字对不上。city_en 为空的行直接不可点。
  修法：给 city 筛选加上 country（或按 city_key 筛，前提是筛选栏支持）。

## 效率

- [x] **8. 鼠标每移动一下，整页重新渲染**
  `TipProvider` 每次 render 都新建 `{ show, hide }`。`onMouseMove` 里调用 `setTip` 后，所有 `useContext(TipContext)` 的消费者（StatsBody、每个 Columns / BarRows、365 格的 CalendarGrid）都会重渲，StatsBody 里的 `calendarYear` / `monthSeries` / `weekdayCounts` 也跟着重算。
  修法：`useMemo(() => ({ show, hide }), [show, hide])`，或者把 tip 状态拆进一个单独的 context。

- [x] **9. 导入期间每次 catalogRevision 变化都重跑一遍全库统计**
  `useEffect` 依赖 `catalogRevision`，导入或标注时它会频繁递增，每次都要整库建一张临时表、跑十几条 GROUP BY。
  修法：给 revision 加防抖（比如停 1 到 2 秒再刷新），或者只在页面可见时刷新。
