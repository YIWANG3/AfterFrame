## P0 正确性 bug（立即修）

- [x] **P0-1 常驻 sidecar 子进程未挂 `error` 事件** — main.js `ensureResidentSidecar`。spawn 异步失败（如打包模式二进制路径错误）成为未捕获异常直接崩主进程；`stdin` 异步 EPIPE 同理。修：`spawned.on("error")` 拒绝 pending 并清理；`stdin.on("error")` 记日志。
- [x] **P0-2 切 catalog 时在途请求错打到新 catalog** — 切换先改 `currentCatalogPath` 再 `stopResidentSidecar()`，被拒请求经 one-shot 回退用新路径重建 `--catalog`，写操作落错库。修：发起调用时捕获 catalog 路径，回退前比对；不一致则以不可重试错误拒绝。
- [x] **P0-3 settings 写队列一次失败永久中毒** — main.js `updateAppSettings` 的 promise 链 rejected 后所有后续写入静默失败。修：链上 `.catch()` 重置，按调用单独返回结果。
- [x] **P0-4 job_runner repaint 注册逻辑与 derived.register_export_file 漂移** — job_runner.py:698-784 是旧副本：preview 失败时 job 标 failed 但资产已半入库；后续修复不会同步。修：`register_export_file` 加 `version_kind` 参数，repaint 改调它。
- [x] **P0-5 serve 模式每请求泄漏 DB 连接** — cli.py `main()` 从不 `connection.close()`。修：main() 中 try/finally 关闭。
- [x] **P0-6 合集→状态过滤不清 `activeCollectionId`** — App.jsx setStatus 路径传了 `collectionId: null` 但没清状态；翻页/刷新会混入或弹回合集数据，标题也错。修：该路径同步清 activeCollectionId（最好把 setStatus 收进 hook 持有不变量）。
- [x] **P0-7 `catalog-changed` 打断进行中的 agent reveal** — useWorkspace catalogChangedRef 不检查 suppress 窗口；"update_assets → show_in_app" 连招会出现 toast 报选中 N 张但实际没选中。修：catalog-changed 处理器尊重 suppress 窗口（或排队到 reveal 完成）。
- [x] **P0-8 小件包**：
  - [x] preview job 失败仍自动链 preview-hd（useWorkspace handleJobFinished 只判 `!cancelled`，应判 `succeeded`）
  - [x] `update_job(error_text=None)` 无法清除旧 error（db.py，用 sentinel 或总是赋值）
  - [x] `update_assets` 中途失败不广播（mcp/server.js，改按资产收集错误并始终广播已变更部分）
  - [x] `formatJobStatus(null)` 缺 `phaseLabel/mode/kind` 字段（main.js，补齐保持两分支一致）
