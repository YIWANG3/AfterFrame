AfterFrame 0.5.29 can update itself: from this version on, a new release is checked for, downloaded and installed from inside the app. Imports are faster on a Mac, importing a folder again reads only what changed, and the people scan and annotation that follow an import now run after every import, and only on its photos. Missing originals become a filter you can use anywhere, and the sidebar can be dragged into your own order.

## Download

| | File | Needs |
|---|---|---|
| **Mac, Apple Silicon** | `AfterFrame-0.5.29-arm64.dmg` | macOS 14 or later |
| **Mac, Apple Silicon, older macOS** | `AfterFrame-0.5.29-macOS12-arm64.dmg` | macOS 12 or 13 |
| **Mac, Intel** | `AfterFrame-0.5.29-macOS12-Intel.dmg` | macOS 12 or later |
| **Windows** | `AfterFrame-0.5.29-x64-setup.exe` | Windows 10 or 11, 64-bit |

The two macOS 12 builds are the same app without People & Pets, Scene Depth and Stickers, which use Apple's on-device models that need macOS 14. On an Apple Silicon Mac with macOS 14 or later, take the first one. The Intel build reads RAW files with an older LibRaw (0.21), which can't decode DNGs compressed with JPEG XL.

The Windows installer isn't signed yet. When Windows says "Windows protected your PC" (Windows 已保护你的电脑), click **More info** (更多信息), then **Run anyway** (仍要运行). LUTs, Stickers, People & Pets and Scene Depth are in the macOS app only for now.

**Coming from 0.5.28 or older, download this version once by hand**, as before: drag it over the old app on a Mac, or run the installer on Windows. Your catalogs and settings stay. Later versions then arrive in the app. This version doesn't change the catalog, so 0.5.28 still opens it.

## New

### Updates from inside the app

- **Settings → About → Software Update** checks for a new version, and **AfterFrame → Check for Updates…** does the same from the menu. **Download** fetches it; it installs when you quit, or at once with **Restart to Update**. That button waits while background tasks run, since they still use files from the running app (#344).
- **The app checks a minute after launch and then once a day.** A new version is announced once, and About carries a dot until it's installed. Turn **Check for updates automatically** off in About to check only when you ask; it is on by default.
- **Each Mac build stays on its own line.** A macOS 12 build is offered macOS 12 builds only, never the one that needs macOS 14.
- **The check carries nothing that identifies your Mac or PC.** It asks GitHub for the latest release's file list. The privacy page says so in section 03.
- An app run straight from the DMG or from Downloads can't replace itself. It still checks, and offers **Download from GitHub** instead, with a hint to move it to Applications.
- On Windows, the downloaded installer runs silently when the app closes.
- The About page now shows the version and the processor it was built for. It used to leave the version out and always say arm64.

### Faster imports

- **JPEG and HEIF photos import in about half the time on a Mac.** Their previews are made with macOS's own Image I/O, which reads a HEIC straight at the preview's size instead of decoding all of it. 500 photos (400 JPEG, 100 HEIC) took 7.4 s instead of 14 s, with a third of the CPU, on an M3 Pro. Other formats, and Windows, are unchanged (#345).
- **Importing a folder again reads only the files that changed.** A photo the catalog already holds as it is on disk (same size and modification time, and the same `.xmp` beside it) is passed over without reading it. 500 unchanged photos took 0.15 s instead of 1.9 s (#347). A library that holds RAW files re-imports through "Match with RAW", and that is quicker too: 250 unchanged RAW+JPG pairs took 0.21 s instead of 1.2 s, scored against their RAWs from what the catalog already knows (#350).
- **A people scan analyses up to three photos at once**, as many as the Mac's cores and memory allow: one on an 8 GB Mac, two on an 8-core Mac with 16 GB, three on a 12-core Mac with 18 GB. 500 photos took about 45 s instead of 116 s on an M3 Pro. A scan uses about 2 GB more memory while it runs (#346).

### What follows an import

- **Every import that adds photos gets its follow-ups:** the people scan and auto-annotation, as Settings ask for. That now includes an import you cancelled part-way, one that failed, one an agent ran with no window open, and one still running when the app quit, which the next launch follows up (#348).
- **Auto-annotate on import covers only the photos that import added.** It used to take every photo in the library without a caption, so turning it on in a large library and importing five photos could annotate thousands on your API key.
- **People scans wait while an import runs**, then go on by themselves. Background Activity shows such a scan as "Waits for the import" (等导入结束). A scan you paused stays paused, and one you resume by hand during an import keeps running.
- **Background analysis waits too.** The colour, look-alike and orientation catch-ups and the HD previews after an import start once the import is over.
- **Background Activity lists the jobs you started first**, then the ones the app started itself, oldest first in each.
- **Cancelling a paused job ends it at once**, instead of showing "Cancelling…" until it was resumed.

For agents, `import_directory` behind a running import is queued instead of refused, `index_people` during an import answers `paused`, `get_job_status` and `list_active_jobs` report `pausedForImport`, and an ended import's result lists its `followups`.

### Missing originals are a filter

- **Original: Missing / On disk** is a new filter condition, the first chip on the filter bar. It shows only while some photo's file is missing, so a library with nothing missing never sees it (#343).
- **It works anywhere:** in a collection, a folder or All Assets, saved in a smart collection's rules, or excluded. The Relink / Remove bar shows wherever the view holds only missing photos, and Remove All only ever reaches those.
- **Verify Files → View** and the statistics page's "Missing from disk" row open All Assets with that condition. The separate Missing Originals view is gone.

For agents, `search_assets` and smart collection rules in `manage_collections` take `missing`; `status: "missing"` still works.

### The sidebar, in your order

- **Drag an entry to another place**: Recently Added, Discover, People & Pets, Tags, Statistics and the rest. **Drag a section by its heading** to put Smart Collections, Collections and Folders in another order. A line shows where it lands (#355).
- Entries move among entries and sections among sections. **All Assets stays first** and doesn't move.
- This Mac remembers the order. An entry you hide keeps its place, and comes back there when you show it again.
- Settings → General → Sidebar, where each entry and section can be switched off, lists them in the same order.

## Changed

- **A mouse click leaves no focus ring behind.** Clicking a button, a tab or a switch no longer leaves it focused, so the next key press doesn't draw a blue ring around it, and Space or Enter doesn't press it again. In the editor, releasing Space after panning the canvas used to press the template or switch clicked last (#342).
- **Keyboard focus has one ring:** a 2 px line in the accent colour, white in the dark theme and near-black in the light one, instead of Chromium's blue and six styles of the app's own. Tab now shows where it is on the sidebar rows, the gallery cards, dialog buttons, the video player and the sort menus, which had no ring.
- **The Inspector's Source section calls the photo's own file File (文件)**, not Asset (成品), which only fitted an export made from a RAW. The lightbox's details pane changes with it (#349).

## Fixed

- **A folded Smart Collections or Folders section gives its room back at once.** Folding one left a blank under its heading, as tall as the rows it had shown, until something else redrew the sidebar (#354).
