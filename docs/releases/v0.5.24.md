AfterFrame 0.5.24 keeps a Finder folder's subfolders when you drag it in, and shows RAW files from cameras that are newer than its RAW decoder, such as the Sony A7 V.

## Download

| | File | Needs |
|---|---|---|
| **Mac, Apple Silicon** | `AfterFrame-0.5.24-arm64.dmg` | macOS 14 or later |
| **Mac, Apple Silicon, older macOS** | `AfterFrame-0.5.24-macOS12-arm64.dmg` | macOS 12 or 13 |
| **Mac, Intel** | `AfterFrame-0.5.24-macOS12-Intel.dmg` | macOS 12 or later |
| **Windows** | `AfterFrame-0.5.24-x64-setup.exe` | Windows 10 or 11, 64-bit |

The two macOS 12 builds are the same app without People, Scene Depth and Stickers, which use Apple's on-device models that need macOS 14. On an Apple Silicon Mac with macOS 14 or later, take the first one. The Intel build reads RAW files with an older LibRaw (0.21), which can't decode DNGs compressed with JPEG XL.

The Windows installer isn't signed yet. When Windows says "Windows protected your PC" (Windows 已保护你的电脑), click **More info** (更多信息), then **Run anyway** (仍要运行). To update, run the new installer: your catalogs and settings stay. LUTs, Stickers, People and Scene Depth are in the macOS app only for now.

A catalog opened by 0.5.19 or later can't be opened by 0.5.18 or older (the folder tree and tag groups added in 0.5.19). 0.5.24 doesn't change the catalog format.

## New

### Keep a folder's subfolders

Dragging a Finder folder that has subfolders onto the sidebar's folders or the Folders page now asks how to file it:

- **Put Everything in One Folder**: what happened before, listed first.
- **Keep the Subfolders**: each subfolder on disk becomes a folder of the same name inside the dropped one, and each photo goes into the folder it sits in. A subfolder with no photos makes no folder.
- **Cancel**: nothing is imported.

Dropping the same folder again finds the folders it made by name, so nothing is duplicated. The dropped folder still shows the whole shoot, since subfolders are included by default. A folder without subfolders (or with only hidden ones, such as `.cache`) doesn't ask, and dropping onto a folder's row works as before (#298).

## Fixed

- **RAW files from cameras newer than LibRaw** get a preview again. A Sony A7 V (`ILCE-7M5`) ARW stayed on "Preparing preview…" because LibRaw rejects the whole file and macOS can't render it either. AfterFrame now shows the largest JPEG the camera embedded in the RAW; on the A7 V that's the full 7008×4672, so the lightbox still zooms to real detail. Cameras LibRaw already knows are unchanged (#299).
